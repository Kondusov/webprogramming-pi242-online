1. IP-адрес
IP-адрес — это уникальный цифровой идентификатор устройства (компьютера, сервера, смартфона) в сети (интернет или локальной). Он нужен, чтобы устройства могли находить друг друга и обмениваться данными. 

Есть две основные версии:

IPv4. Адрес выглядит как четыре числа от 0 до 255, разделённые точками (например, 192.168.1.1). Он 32-битный, поэтому количество возможных адресов ограничено (около 4,3 млрд).

IPv6. Решение проблемы нехватки адресов. Адрес состоит из восьми групп шестнадцатеричных цифр, разделённых двоеточиями (например, 2001:db8::1). Он 128-битный, что даёт практически неограниченное количество комбинаций. 
Обычно IP-адрес состоит из двух частей: номера сети (определяет, к какой сети подключено устройство) и номера хоста (конкретное устройство в этой сети). Для выделения этих частей используют маску подсети. 

2. Протокол TCP/IP
TCP/IP — это не один протокол, а целый стек (набор) протоколов, на котором построен интернет. Название происходит от двух ключевых компонентов: IP (Internet Protocol) и TCP (Transmission Control Protocol).

IP работает на сетевом уровне. Его задача — маршрутизация: он отвечает за то, чтобы пакет данных добрался от отправителя к получателю, используя IP-адреса. Сам по себе IP не гарантирует доставку — он просто «направляет» пакеты. 
TCP работает на транспортном уровне. Он добавляет надёжность: устанавливает соединение, следит за тем, чтобы данные дошли целиком и в правильном порядке, повторно отправляет потерянные сегменты, управляет скоростью передачи. 
А вот протоколы, которые вы перечислили (HTTP, HTTPS, SMTP, FTP, SSH), работают поверх TCP (реже — поверх UDP). Они относятся к прикладному уровню и определяют, как именно приложения обмениваются данными:

HTTP — передача гипертекста (загрузка веб-страниц).
HTTPS — то же самое, но с шифрованием (безопасный HTTP).
SMTP — отправка электронной почты.
FTP — передача файлов между компьютерами.
SSH — защищённый удалённый доступ к системе (например, для управления сервером). 

3. Сравнение TCP и UDP
Оба — транспортные протоколы, но решают задачи по-разному. 


TCP — протокол с установлением соединения. Перед передачей данных стороны «договариваются» (трёхстороннее рукопожатие). Он гарантирует доставку, порядок пакетов, повторно отправляет потерянные, контролирует нагрузку в сети. Идеален там, где критична целостность: веб-страницы, загрузка файлов, электронная почта, базы данных. Минус — из-за механизмов надёжности задержка может быть выше. 

UDP — протокол без установления соединения. Отправитель просто шлёт пакеты (датаграммы), не проверяя, готов ли получатель, не дожидаясь подтверждений и не восстанавливая порядок. Он быстрее, но не гарантирует доставку и порядок. Его выбирают, когда важнее скорость, а небольшие потери допустимы: потоковое видео и аудио, онлайн-игры, голосовая связь (VoIP), DNS-запросы. 

4. Использование портов и сокетов
Порт — это числовой идентификатор (от 0 до 65535), который помогает направить данные конкретному приложению на устройстве. Представьте так: IP-адрес — это адрес дома, а порт — номер квартиры. Для стандартных сервисов закреплены определённые порты: 80 — HTTP, 443 — HTTPS, 22 — SSH, 25 — SMTP. Диапазоны условно делят на системные (0–1023), зарегистрированные (1024–49151) и динамические (49152–65535, используются ОС для временных исходящих соединений). 
Сокет — это комбинация IP-адреса и номера порта. Именно сокет уникально идентифицирует «точку входа» для обмена данными между приложениями. С точки зрения программиста сокет — это программный интерфейс (API), через который приложение отправляет и принимает данные. Когда приложение хочет общаться по сети, оно создаёт сокет. 

На практике это работает так: браузер (клиент) получает от ОС временный порт, отправляет пакет на сервер (например, на порт 443), сервер обрабатывает запрос и отправляет ответ обратно, используя порт клиента. Сервер может одновременно обслуживать множество клиентов на одном порту, потому что у каждого клиента свой уникальный IP или свой временный порт — в итоге пятёрка параметров (протокол, src_IP, src_port, dst_IP, dst_port) уникальна для каждого соединения.
